## Implementation

New reports use `transcript-v4-isolated` / `interview-grading-v4`. V3 let the model see all answers together, so a valid quote did not prevent prose feedback referring to another answer. V4 sends one question and its confirmed answer per request, plus only role/seniority/type/difficulty/language. Each result must contain exactly that question ID. Both evidence and double-quoted feedback/summary text must belong to that answer. Unconfirmed original transcripts and observations are excluded. Summaries are assembled without another model call, labeled by question and interleaved up to the existing limit. Unanswered questions are scored locally.

Correctness/relevance 40%, reasoning/evidence 35%, text clarity/structure 25%, half-up rounding, all-question denominator, coverage and full-credit eligibility are preserved. No score ceiling or forced ordering is introduced. Historical reports retain saved versions/scores. Up to six sequential grades increase logical text calls from eight to thirteen for a full session, before failure retries; audio/image calls are additional. Evaluation leases are at least 360 seconds, others use configured leases (180 seconds default). Stale-token fencing and unique reports remain unchanged. A failed evaluation retries the whole batch and can repeat already completed upstream work; no partial grades are persisted. Provider budgets and latency remain an operational consideration.

Recorder errors, unexpected stops and ended/muted microphones now discard partial blobs and give re-recording guidance. Previously an error could still fire `onstop` with data and queue transcription. Explicit stop, background-stop and bounded-duration behavior remain available; successful recordings still require transcript review and confirmation. Simulated browser failures verify this logic, not physical interruption reliability.

Tracked first-party frontend, backend, scripts, configuration, worker and tests were reviewed for unnecessary comments. Removed stale phase-adapter instructions, an obsolete fixture history note, redundant CSS section labels, obvious UI/test/config narration. Preserved authorization, consent/privacy, locking, idempotency, browser workarounds, test intent, attribution, directives and framework-managed instructions. The MediaPipe worker comment now accurately separates local inference from the separately consented upload path. Parsed TOML is identical before/after comment removal. No dependency, vendored code, generated API or historical migration was edited for cleanup.

The README now describes the complete application, real directory boundaries and tools, PowerShell setup, migration targets, public/server variables, usage windows, test isolation, privacy and current limitations.

## Reproducible remaining manual checks

Use a consenting tester and non-sensitive answers, a supported secure origin and a specific browser/OS/device/codec record. Any additional visible person must independently consent. Keep raw audio/images, private answers and auth tokens out of evidence. Record false warnings and misses by scene; never derive an accuracy percentage from these checks.

1. **Physical audio/adverse conditions:** pass devices and audio playback; try silence then low-volume speech, then one answer with ordinary background noise. Confirm useful re-recording guidance or review/correct errors. During another recording, disconnect/mute the microphone and verify partial audio is discarded with a safe retry. Interrupt the camera separately and verify availability guidance. An injected browser event proves code behavior only; repeat on the physical device.
2. **Network, processing and deadline:** after a ready transcript, disconnect/reconnect networking and submit/retry; verify one immutable answer and one session allowance. Test a controlled provider failure without exhausting quota. Start transcription close to the real deadline, let completion win, and confirm no late answer, stale grade or retained temporary audio. Reload an unfinished session and verify saved answers/ready transcripts persist, the original deadline remains, local device checks repeat and unsent recording loss is disclosed.
3. **Face/focus observations:** leave frame for more than four seconds, return for more than two, and repeat within/after the ten-second cooldown. Compare warning and episode/recovery timeline. Repeat with multiple consenting people; note distance/light/occlusion and any miss. Hide/return and blur/refocus; verify coalescing, bounded warnings, coverage gaps and frozen report summary. No observation may change performance marks.
4. **Optional images:** opt in separately; compare clearly visible phone, no phone and ambiguous/occluded object scenes at eligible sample intervals. Verify repeated-positive warning behavior, uncertain results without accusation and recovery. Withdraw while a request is pending; inspect that no new upload occurs and the late result is unavailable/ignored. Use controlled provider failure/capacity simulation without consuming the real quota; submit a ready transcript throughout. An already-sent frame cannot be recalled. No image/video retry queue or full-video file should exist.
5. **Per-device support:** repeat the positive journey and the interruption/background/return cases on each available physical configuration. Record selected devices, actual MIME, playback/transcription, MediaPipe readiness, responsive controls and keyboard traversal from setup through report. Record assistive technology/version if used. Complete, refresh and use another signed-in browser context, then verify stopped tracks and absence of active detector/listener/recording work.
